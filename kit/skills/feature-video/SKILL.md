# 機能説明の「動く紙芝居」を作る（動画で要件を合わせる）

作る前に、完成したときの見え方を30秒の動く紙芝居にして、お客さんと要件を合わせる。
出力はブラウザで開くだけで自動で再生する HTML 1枚。

## 同梱ファイル

- `templates/scenes.md` … 場面表の雛形と、良い説明動画の物差し。手順2で読む
- `templates/player.html` … 動く紙芝居の型。再生の仕組み・字幕・進み具合の帯・画面の部品（スマホの枠・パソコンの枠・表・流れの図）が入っている。手順4で読む

## 手順

1. 入力（提案スライドの md か、ヒアリングメモ）を読み、見せる機能を3〜4つに絞る。
2. `${CLAUDE_SKILL_DIR}/templates/scenes.md` を読み、同じ形で `out/scenes.md` に場面表を書く。4〜6場面・合計30秒前後。
3. 場面表を見せ、直す所が無いか聞く。「そのまま進めて」と言われていれば聞かずに進む。
4. `${CLAUDE_SKILL_DIR}/templates/player.html` を読み、`out/feature.html` に写す。書き換えるのは3か所だけ: `<title>`、`#stage` の `data-title`、「ここから場面」〜「ここまで場面」の中身。
5. 場面表の1行を `<section class="scene" data-sec="秒数" data-caption="字幕">` 1つにする。画面は型の部品（`.phone` `.pc` `.card` `.tbl` `.flow` など）で描き、出す順は `class="in" style="--d:1.2s"` で決める。
6. 点検する: 場面の数と秒数の合計が場面表と同じか／字幕が25字までか／`http` と `<img` と `<link` が無いか（外部の部品を読まない）。
7. 報告する: できたファイルの場所、合計の秒数、お客さんに聞く質問3つ、下の「開き方」と「動画ファイルにするには」。

## 開き方（報告にそのまま書く）

- Mac: `open out/feature.html`　Windows（PowerShell）: `start out\feature.html`
- 開くと自動で再生する。スペースで一時停止、← → で前後の場面。末尾に `#3` を付けると3場面目から始まる

## 動画ファイルにするには（報告にそのまま書く。任意）

- Mac: Shift＋Command＋5 →「画面全体を収録」か「選択部分を収録」→「収録」。止めるのはメニューバーの停止ボタン。デスクトップに .mov で保存される（出典: https://support.apple.com/ja-jp/102618 ）
- Windows: Snipping Tool で Windows ロゴ キー＋Shift＋R → 範囲を選ぶ →「開始」→「停止」→ 保存（出典: https://support.microsoft.com/ja-jp/windows/snipping-tool-を使ってスクリーンショットをキャプチャする-00246869-1843-655f-f220-97299b865f6b ）
- 収録の前にブラウザを全画面にして、`#1` から再生し直す

## 守ること

- **声は入れない。字幕だけ。** 読み上げ（TTS）や有料の API は使わず、API キーも聞かない
- 外部の部品（CDN・Web フォント・画像の URL）を読まない。画面は HTML と CSS の図形で描く
- アプリの画面は架空のもの。実在の製品のロゴ・色・画面に似せない
- スマホの枠の中は、入力欄・ボタン・写真の列を合わせて5つまで（多いと下が切れる）
- 字幕は1場面につき1文・25字まで。画面を揺らさない（動きは、ものが出る・ボタンを押す・場面が替わる、だけ）
- 入力に無い機能や数字を足さない。数字は灰色の帯（`.mask`）で伏せ、足したい機能は「提案（要確認）」と書く
- 会社名は入力の書き方のまま使う（「（架空）」などの注記も消さない）
- 型の再生の仕組み（`<script>` と `<style>`）は直さない
