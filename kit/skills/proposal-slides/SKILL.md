# 提案スライドを作る

ヒアリングメモを、7節の決まった順の提案スライドにする。

## 同梱ファイル

- `templates/proposal.md` … スライドの雛形（表紙＋7節＋確認したいこと）。手順3で読む
- `checklist.md` … 出す前の点検5項目。手順5で読む
- `theme.css` … 見た目（白地・16:9）。手順6で使う

## 手順

1. ヒアリングメモを、行番号つきで読む。どのファイルか分からなければ聞く。
2. 「誰に・何を分かってほしいか・何をしてほしいか」を1行で決め、表紙の下に書く。
3. `${CLAUDE_SKILL_DIR}/templates/proposal.md` を読み、同じ順で `out/proposal.md` を書く。順番は変えない（課題の事実が先、解決の方式は4番目）。
4. 数字と事実には、ページの下に出典を書く。形は「出典: ヒアリングメモ 12行目」。
5. `${CLAUDE_SKILL_DIR}/checklist.md` の5項目で点検し、直してから次へ進む。
6. 書き出す（作業フォルダで実行）:
   `npx -y @marp-team/marp-cli@4.5.1 out/proposal.md --theme-set ${CLAUDE_SKILL_DIR}/theme.css -o out/proposal.pdf --no-stdin < /dev/null`
7. できたファイルの場所、点検の結果、「要確認」の一覧を報告する。

## 出力先

- `out/proposal.md`（中身）と `out/proposal.pdf`（見せる用）
- PPTX は頼まれた時だけ。`-o out/proposal.pptx` に変える（各ページが画像になり、文字は直せない）

## 守ること

- メモに無い数字を作らない。出典の無い数字は載せないか、「要確認」と書く
- 効果の数字は、メモにある今の手間（時間・回数）から計算できるものだけ。計算の式も書く
- 1ページは箇条書き5行か、表5行まで。長い文は短く言い換える
- 分からない所は「要確認」と書き、最後のページ「確認したいこと」に集める
- 仕上げは人がする。最後に「人が直すべき所」を3つまで挙げる
